# SIGOVS — PROJECT CATALOG

A visual project-preview portal for every repository owned by
[@Sigovs](https://github.com/Sigovs). One page, one screenshot per project,
recognisable before you read a single title.

The catalog discovers repositories automatically. Create a repo tomorrow, deploy
it, run `npm run catalog:update`, and a new card appears with a fresh screenshot.
Nothing is hardcoded.

---

## Run it

```bash
npm install
npm run catalog:update    # pull GitHub, capture thumbnails  (~3 min first time)
npm run dev               # http://localhost:5180
```

After the first run, `npm run dev` alone is enough — the catalog is on disk.

| Command | What it does |
| --- | --- |
| `npm run catalog:update` | The one command. Sync → scan local clones → capture missing thumbnails. |
| `npm run dev` | The portal at `localhost:5180`. |
| `npm run sync` | GitHub metadata only. Seconds. |
| `npm run screenshots` | Thumbnails only. |
| `npm run scan:local` | Re-find local clones for the *Open in VS Code* action. |
| `npm run build` | Static site into `dist/`. Deployable anywhere. |

Useful flags:

```bash
npm run catalog:update -- --no-screenshots   # metadata only, seconds
npm run catalog:update -- --force            # recapture every thumbnail
npm run catalog:update -- --max-age 30       # also refresh shots older than 30 days
npm run screenshots -- --only KERBECK,PATTON # redo two projects
```

## How the pieces fit

```
GitHub API
    ↓  scripts/sync-github.mjs        every repo you own + preview URL discovery
data/repos.json                       generated, committed, never hand-edited
    ↓
data/catalog-overrides.json           YOURS. titles, categories, pins, manual images
data/local-paths.json                 generated by scan-local, enables VS Code
public/thumbnails/                    WebP cache + manifest.json
    ↓  merged at dev-server / build time
catalog.json                          what the browser loads. One request.
    ↓
PROJECT CATALOG UI
```

The browser never calls GitHub. The whole grid renders from a single 43 KB JSON
file, so browsing is instant and GitHub rate limits are irrelevant.

## GitHub sync

`npm run sync` lists every repository the account owns, then for each one works
out where its live site is:

1. the repository **homepage** field, if set
2. the **GitHub Pages** deployment (`/repos/{repo}/pages`), which is where 41 of
   your 48 projects live
3. a link in the **README**, but only one explicitly labelled *live / demo /
   preview* — a bare URL in prose is not treated as evidence
4. otherwise `null`, and the card gets a generated placeholder

It never guesses a URL from a repository name. A card that opens a 404 is worse
than a card that admits it has no preview.

### Authentication

The token is only ever read by Node. It is never bundled into the browser.

Resolution order:

1. `GITHUB_TOKEN` from `.env` (copy `.env.example`)
2. the GitHub CLI, if you are already logged in — `gh auth token`
3. nothing: public repositories only, 60 requests/hour

You are currently logged in through `gh`, so the sync already sees your two
private repositories with no setup at all.

## Thumbnails

Six sources, tried in order. The first that works wins.

| # | Source | Notes |
| --- | --- | --- |
| 1 | `thumbnail` in your overrides | An absolute URL or a file in `public/thumbnails/`. |
| 2 | An explicit preview image in the repo | `preview.png`, `cover.jpg`, `og-image.webp`… at the repo root. |
| 3 | **A live screenshot** | Playwright, 1440×900 at 2×. This is where most come from. |
| 4 | GitHub's open-graph card | Off by default — it looks like GitHub. Enable with `--opengraph`. |
| 5 | A representative image found inside the repo | Only when there is no live URL. Prefers `hero`/`cover`/`screenshot` paths. |
| 6 | A generated placeholder | Project initials on a technical mesh. Drawn in CSS, so it can never break. |

Screenshots are captured viewport-only from the top of the page, with reduced
motion on and animations paused, so a scroll-driven build is caught in its hero
state rather than halfway through a GSAP timeline. The page is not scrolled —
scrolling would advance a pinned timeline.

Each capture writes two files:

```
public/thumbnails/kerbeck.webp        1600×1000   drawer, retina cards
public/thumbnails/kerbeck@sm.webp      800×500    grid
```

**Nothing is recaptured unless the repository has been pushed to since last
time.** A capture that fails keeps the previous thumbnail and records the error
in `public/thumbnails/manifest.json`. Broken images never reach the UI.

## Overriding a project

Everything presentational lives in **`data/catalog-overrides.json`**. Edit it by
hand; nothing overwrites it. `npm run sync` only ever *adds* a stub for a
repository it has not seen before.

```jsonc
{
  "categories": ["AAN", "Client Sites", "Automotive", "3D / Experimental", "Personal", "Archive"],

  "projects": {
    "AAN_PPREVIEW_CHICAGOMOTORCARS": {
      "title": "Chicago Motor Cars",
      "subtitle": "AAN Preview",
      "category": "AAN",
      "pinned": true
    },

    "Midwest-cobras": {
      "title": "Midwest Cobras",
      "subtitle": "3D Scroll Experience",
      "tags": ["GSAP", "Three.js"],
      "thumbnail": "thumbnails/my-own-shot.webp",
      "previewUrl": "https://a-custom-domain.com/",
      "status": "complete"
    }
  }
}
```

Every field is optional:

| Field | Effect |
| --- | --- |
| `title` | The big name on the card. Falls back to automatic cleanup. |
| `subtitle` | One quiet line under it. |
| `category` | Must be one of `categories`. Drives the filter bar. |
| `tags` | Extra chips. Language is added automatically. |
| `previewUrl` | Overrides Pages detection — **and this is what gets screenshotted.** |
| `thumbnail` | Skips screenshotting entirely and uses your image. |
| `pinned` | Sorts to the front of the grid with a small brass pin. |
| `hidden` | Removes the project from the catalog. |
| `status` | `active` · `concept` · `development` · `complete` · `archived` |
| `localPath` | Absolute folder path. Enables *Open in VS Code*. Usually auto-filled. |

### Change one title

```jsonc
"VEGAS_UPD": { "title": "Vegas Auto Gallery", "subtitle": "Site update" }
```

Save the file. In dev the page updates immediately — no restart.

### Change one image

Drop a file in `public/thumbnails/`, then:

```jsonc
"KERBECK": { "thumbnail": "thumbnails/kerbeck-hero.webp" }
```

### Change one preview URL

```jsonc
"PATTON": { "previewUrl": "https://the-real-url.com/" }
```

Then `npm run screenshots -- --only PATTON`.

## Automatic titles

When no `title` is set, the repository name is cleaned up:

```
Wes_Financial_Auto              →  Wes Financial Auto
Midwest-cobras                  →  Midwest Cobras
cmc_concept4                    →  CMC Concept 4
AAN_MASTER_2026                 →  AAN Master 2026
-Exotic-Motorsports-of-Oklahoma →  Exotic Motorsports of Oklahoma
VEGAS_UPD                       →  Vegas Update
```

Known acronyms stay upper-case, short designations with a digit are treated as
names (`GD2`, `K2`), and connector words stay lower-case. The raw repository
name is always shown underneath, so you can still find things by it.

## Open in VS Code

`npm run scan:local` walks your work folders, reads each `.git/config`, and
matches the real `origin` remote to a repository. It never guesses a path from a
name — `C:\____WORK\CHICAGO MOTOR CARS` is `AAN_PPREVIEW_CHICAGOMOTORCARS`, and
no amount of string matching would find that.

27 of your 48 repositories currently resolve to a local clone. Those show a
**VS Code** button in the detail drawer; the rest simply do not.

Point it somewhere else with `CATALOG_LOCAL_ROOTS` in `.env`, or:

```bash
npm run scan:local -- --root "D:\clients" --depth 3
```

## Keyboard

| Key | Action |
| --- | --- |
| `/` or `Ctrl/⌘ K` | Focus search |
| `Esc` | Clear search · close the drawer |
| `Tab` | Everything is reachable; the drawer traps focus and restores it on close |

Filters, sort, view and search are all reflected in the URL, so any view of the
catalog is a link you can bookmark or send.

## Deploying (optional)

`.github/workflows/catalog.yml` re-syncs, recaptures and publishes to GitHub
Pages daily and on demand. It needs Pages set to *GitHub Actions* in the
repository settings, and — to include private repositories — a `CATALOG_TOKEN`
secret with `repo` scope.

The local catalog does not depend on any of it.

---

## Stack

Vite and vanilla ES modules. No framework, no CSS library, no state manager —
17 KB of JavaScript for the whole portal. Playwright and sharp are dev-only and
never ship to the browser.
